svgplot

markdown 문서에 넣을 정적 SVG 차트를 만드는 Python 패키지.

import svgplot as sp

data = {"day": [1, 2, 3, 4, 5], "sales": [10.0, 15.0, 7.0, 20.0, 12.0]}
sp.lineplot(data, x="day", y="sales").save("chart.svg")

배경

기존 라이브러리를 조사하면서 목표를 "markdown 문서에 넣을, 고치기 쉬운 정적 SVG"로 잡았다. 조사에서 확인한 각 라이브러리의 자리는 이렇다.

라이브러리 SVG 출력
pygal SVG를 직접 만들지만 통계 계산이 없다
matplotlib SVG 백엔드가 좌표를 덤프한다
seaborn 자체 SVG 출력이 없다(matplotlib에 위임)
Bokeh Python이 SVG를 만들지 않는다(Canvas/WebGL, export는 헤드리스 브라우저)

seaborn이 matplotlib을 감싸서 제공하는 기능 목록을 "실사용자가 반복적으로 필요로 한 것"의 증거로 보고, 그 목록(tidy 데이터 시맨틱 매핑, 자동 집계, 패싯)을 기능 범위의 출발점으로 삼았다. 호출 문법도 data=, x=, y=, hue= 형태를 따른다.

정적으로 만든 이유

markdown 렌더러에 <img src="chart.svg">로 삽입된 SVG는 브라우저가 이미지로 취급한다. 그 안에서는 <script>가 실행되지 않고 :hover도 대부분 동작하지 않는다. 이 제약을 나중에 우회할 대상이 아니라 설계의 출발점으로 두었다. 패키지는 JS를 방출하지 않으며, <script> 태그와 인라인 style= 속성은 직렬화 단계에서 차단된다.

같은 이유로 텍스트 폭을 실제로 측정하지 않는다. SVG 문자열 생성기에는 렌더러가 없어 글리프를 잴 수 없고, 그래서 레이아웃은 측정 없이 동작하는 방식(고정 여백 프리셋, 폭 추정, 라벨 회전)으로 짜여 있다. 추정이 어느 방향으로 틀리는지는 charts/_textwidth.py에 적혀 있다.

범위 밖

다음은 넣지 않기로 한 것이다.

  • 등고선·hexbin·3D·수식(mathtext) 렌더링
  • 클러스터맵, pair/joint grid — 복합 레이아웃 엔진이 필요하다
  • logistic·robust·lowess 회귀 — statsmodels 의존이 생긴다
  • 애니메이션, 탭 전환 UI, 내부 스크롤 — markdown에서 재현되지 않는다
  • JavaScript

차트 16종 — 갤러리에서 볼 수 있다
시맨틱 매핑 hue=, size=, col=/row= 패싯(패널이 축을 공유한다)
축 선형·로그·시간축, xlim=/ylim=
테마 ~25키 스키마, 프리셋 5종 × 컨텍스트 4종, 시드 색에서 파생하는 파라메트릭 테마
출력 SVG 문자열·파일, markdown, Jupyter 표시, PNG(선택 의존성)
접근성 모든 차트가 role="img"·<title>·<desc>를 낸다. <desc>는 차트 종류, 데이터 규모, 값 범위를 적는다
의존성 런타임 의존성 없음. numpy는 테스트에서 대조용으로만 쓴다

같은 입력은 같은 SVG를 낸다. 난수를 쓰는 곳(regplot의 부트스트랩)은 시드를 인자로 받고 기본값이 고정되어 있다.

알아둘 것

GitHub는 렌더된 markdown에서 인라인 SVG를 제거한다. chart.save("x.md")로 만든 문서를 github.com에서 보면 각주 표만 보이고 그림은 보이지 않는다. MkDocs·Sphinx·VS Code 미리보기에서는 둘 다 렌더된다.
