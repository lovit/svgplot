## A1. 차트 타입 인벤토리

`galleries/plot_types/`(matplotlib이 스스로 큐레이션한 치트시트) 37개 — SVG 부적합한 `3D/`(9개) 제외 시 27개:

| 계열 | 개수 | 데이터 형태 | 예시 |
|---|---|---|---|
| basic | 7 | 1D 배열 | plot, scatter, bar, fill_between, stackplot, stairs, stem |
| stats | 9 | 1D 샘플/2D 그룹 | boxplot, violinplot, errorbar, ecdf, hist, hist2d, hexbin, eventplot, pie |
| arrays | 7 | 2D meshgrid | imshow, pcolormesh, contour, contourf, quiver, barbs, streamplot |
| unstructured | 4 | 산점→삼각분할 | triplot, tripcolor, tricontour, tricontourf |
| 3D | 9(제외) | — | SVG 비적합 |

`_axes.py`의 public 메서드는 69개 — plot_types 27종 외 나머지는 레이아웃/텍스트/기준선/신호처리(acorr/psd/specgram 등)로 "플로팅이 아닌" 구조/장식/신호처리 메서드다.

**SVG 관점 관찰**: basic(7)+stats(9)=16종은 pygal과 겹치는 1차 타깃. arrays/unstructured(11종)는 픽셀/그리드/삼각분할/유선적분 기반이라 SVG 벡터 요소로 표현하려면 셀 수만큼 `<rect>`/`<path>`가 필요해 파일 크기·구현 난이도가 급격히 커진다(1차 스코프 제외 후보).

## A2. 데이터 입력·시맨틱 매핑

- list/array 직접 위치 인자: `plt.plot([1,2,3],[1,4,9])`
- `data=` kwarg: dict-like 객체를 넘기고 필드는 문자열 키로 참조(`plt.scatter('a','b', data=data)`) — pyplot/axes 9개 메서드에 `DataParamType` 존재
- 범주형(문자열) x축: 문자열 리스트를 직접 전달, `category.py`가 `units.ConversionInterface`를 구현해 정수로 변환
- `units` 모듈: 커스텀 타입(datetime 등)→숫자 변환을 등록하는 확장 포인트(`ConversionInterface`) — "값→float 변환기 레지스트리"로 범주형/시간축이 통일되어 있음

**핵심**: `scatter`의 `c=`/`s=`는 이미 계산된 값 배열을 그대로 받는 raw 파라미터다. **hue/size 같은 "컬럼명→미학 채널 자동 매핑" 개념이 코어에 전혀 없다** — 이건 seaborn이 얹는 레이어.

## A3. API 문법

두 인터페이스가 공존:
- **pyplot(상태형)**: `plt.plot(...)`, 마지막 Figure/Axes를 암묵 추적(`plt.gcf()`/`plt.gca()`)
- **OO(명시형)**: `fig, ax = plt.subplots(); ax.plot(...)`

`pyplot.py`의 196개 top-level 함수 대부분이 `gca().<method>()`를 감싸는 autogenerated boilerplate — API 표면이 크고 이중 유지보수 비용이 있다.

### CJK 하위질문
matplotlib 3.6+부터 백엔드가 하나의 Text 인스턴스 내에서 여러 폰트를 글리프 단위로 교체 사용(`family=['DejaVu Sans','Noto Sans CJK JP','Noto Sans TC']`)하는 fallback 체인을 지원한다. **다만 `matplotlibrc` 기본 `font.sans-serif`에는 CJK 폰트가 전혀 포함되어 있지 않아, 기본 상태에서 CJK는 지원되지 않고 사용자가 수동 지정해야 한다.**

## A4. 스타일·테마 시스템 (rcParams)

`rcsetup.py`의 `_validators`에 **344개** 키. 네임스페이스 상위 분포: boxplot 37, axes 33, figure 24, ytick/xtick/legend 21, lines 17... `mpl-data/matplotlibrc`(849줄)가 전량 주석 포함 마스터 기본값.

`style.use()`/`style.context()`로 31개 내장 `.mplstyle` 프리셋 적용(영구/스코프 한정). 스타일 리스트 합성(`use(['a','b'])`, 뒤가 우선)도 가능. 우선순위: **런타임 kwargs > style.use > matplotlibrc**.

**경험적 최소 테마 스키마**(31개 스타일시트 중 오버라이드 빈도 상위): `axes.prop_cycle`(20회), `patch.facecolor`(15), `grid.color`/`axes.grid`/`axes.facecolor`/`axes.edgecolor`(13), `figure.facecolor`(12), `ytick.color`/`xtick.color`/`grid.linestyle`(11)... **344개 키 중 실제 "테마 정체성"을 만드는 데는 약 20~25개면 충분**하다는 것이 핵심 발견 — SVG 패키지의 테마 스키마 설계에 직접 참고 가능한 수치.

`_STYLE_BLACKLIST`(14개, backend/toolbar 등 비-시각 rcParams)는 "시각적 테마"와 "렌더링 설정"을 분리하는 근거.

## A5. 컬러 팔레트 엔진

4개 독립 축으로 분리되어 있음:
1. **단일 색상 사전**: `BASE_COLORS`(8), `TABLEAU_COLORS`(10), `CSS4_COLORS`(148), `XKCD_COLORS`(947)
2. **정성 컬러 사이클**: `ColorSequenceRegistry`, 기본 prop_cycle=tab10
3. **연속 컬러맵**(4계열): Sequential(perceptually-uniform: viridis/plasma/inferno/magma/cividis 5종 + classic ~24), Diverging(PiYG 등 9 + 신규 다크모드용 berlin/managua/vanimo), Cyclic(twilight 등 3), Qualitative(13), Misc(~17, jet 등 문제 있는 것 포함)
4. **정규화(Normalize)**: `Normalize`/`LogNorm`/`PowerNorm`/`TwoSlopeNorm`/`CenteredNorm`/`BoundaryNorm`/`SymLogNorm`/`AsinhNorm` — Colormap과 완전히 분리된 조합 가능 객체(로그축 히트맵 등에 재사용)

`ListedColormap`(이산) vs `LinearSegmentedColormap`(보간)의 명확한 분리가 "카테고리형 채우기" vs "연속형 히트맵 채우기"에 직결된다.

## A6. 타이포그래피 & 레이아웃

**레이아웃 3단 계층**: 저수준(`GridSpec`/`SubplotSpec`, 명시적 좌표) → 중간(`subplots`/`subplot_mosaic`로 그리드 일괄 생성) → 상위(`constrained`/`tight`/`compressed` 엔진이 사후 자동보정). `subplot_mosaic`의 "이름 붙은 딕셔너리 반환"(`axd['plot']`)은 배열 인덱스보다 인체공학적인 API 선례.

텍스트: `Text` 클래스의 통일된 속성표(ha/va/rotation/bbox/fontproperties), `annotate`의 다중 좌표계(data/axes fraction/offset points) 분리, 내장 경량 mathtext(TeX 서브셋 자체 구현, 외부 의존성 없음).

**핵심 리스크(전체 조사에서 가장 중요한 발견 중 하나): 모든 자동 레이아웃(`constrained_layout`, `tight_layout`, legend 자동 배치, tick label 겹침 회피)은 렌더링된 텍스트의 실제 bbox 측정에 의존한다.** `constrained_layout`은 매 draw마다 `-bbox.x0 + pos.x0 + w_pad` 형태로 margin을 계산하고, 이 측정은 FreeType 기반 glyph metrics(`RendererSVG.get_text_width_height_descent`가 내부적으로 `text2path`→FT2Font 호출)가 있어야만 가능하다. **순수 SVG 문자열 생성기(폰트 엔진 없음)에는 이 경로가 없다.** matplotlib의 SVG 백엔드도 이 능력을 확보하기 위해 FreeType 폰트 엔진을 통째로 내장하고 있다. 즉 자동 레이아웃 기능을 원한다면 (a) 폰트별 근사 advance-width 테이블, (b) 고정 여백 휴리스틱, (c) freetype-py/harfbuzz 등 폰트 셰이핑 라이브러리 임베드 중 하나를 선택해야 한다.

## A8. 출력·인터랙션·확장성 (SVG 백엔드)

**핵심 판정: matplotlib의 SVG 출력은 "geometry dump" 방식이다 — pygal과 정면으로 대비된다.**

`backend_svg.py`(1396 LOC)의 `_write_default_style`이 남기는 전역 CSS는 문서 전체에서 `*{stroke-linejoin:round;stroke-linecap:butt}` **단 한 줄**뿐이다. fill/stroke/opacity/font-size 등 실제 시각 속성은 `_get_style_dict`가 매 `<path>`/`<text>`/`<use>` 엘리먼트마다 인라인 `style="..."`로 재계산해 하드코딩한다. `<g id="...">`로 그룹은 만들지만 CSS 클래스 셀렉터(`.axis` 등)는 없다. **결과: 산출된 SVG를 외부 CSS/다크모드로 재테마하려면 모든 style 속성을 개별 파싱·치환해야 한다.**

`svg.fonttype` 두 모드: `'path'`(글리프를 벡터 경로로 구움, 폰트 비의존적이지만 텍스트 선택/편집 불가·파일 큼) vs `'none'`(실제 `<text>`, 파일 작고 편집 가능하지만 뷰어 폰트 의존). 마커는 `<defs>`+`<use>`로 1회 정의 후 재사용.

애니메이션(`FuncAnimation` 등)과 위젯(`Button`/`Slider` 등)은 GUI 이벤트 루프(`mpl_connect`)에 의존해 **정적 SVG 출력과 완전히 분리된 세계**다. SVG 자체의 SMIL/CSS animation/`<script>` 인터랙션과는 무관 — 참고할 코드가 없다.

## A9. 접근성

- `okabe_ito` 컬러맵(색맹 안전 8색), `tableau-colorblind10.mplstyle`, `seaborn-v0_8-colorblind.mplstyle`, `petroff6/8/10.mplstyle`(Petroff 2021 논문 기반) — **4종이나 중복 존재하지만 "정답 하나"가 없고 전부 옵트인**(기본 prop_cycle=tab10은 색맹 최적화 아님).
- `cividis`는 CVD 시뮬레이션 기반으로 설계된 컬러맵.
- 문서에 "Color vision deficiencies" 절, 그레이스케일 변환 분석(흑백 인쇄 시 열화 양상)이 있어 **문서화 품질은 높으나 런타임 검사/경고 API는 없음**(`is_colorblind_safe(cmap)` 같은 함수 부재).

## 강점 / 약점 종합

**강점**: 방대하고 성숙한 rcParams·컬러맵·레이아웃 생태계, `units`/`Normalize` 등 조합 가능한 확장 포인트 설계, mathtext 자체 구현, CJK 폰트 fallback 체인 지원(기본값은 아님), 접근성 팔레트 다수 내장.

**약점**: 시맨틱 채널(hue/size) 부재, pyplot의 196개 autogenerated 함수로 인한 API 표면 비대, **자동 레이아웃이 폰트 렌더러 존재를 전제**(순수 SVG 생성기에 이식 불가), SVG 출력이 CSS 재테마 불가능한 geometry dump 구조, 애니메이션/위젯이 SVG와 분리된 별도 인프라, 접근성 기능이 전부 옵트인이고 런타임 검증 없음.
