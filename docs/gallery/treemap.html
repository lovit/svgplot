svgplot · 갤러리

treemap

값을 면적에 비례하는 타일로 캔버스를 채운다. squarified 배치(Bruls 2000)를 쓰고 단일 레벨만 다룬다.

데이터
values: 수치(음수 불가, 합 0 불가) · labels(선택): 타일 이름

데이터

import svgplot as sp

STORAGE = {
    "종류": ["이미지", "동영상", "문서", "로그", "백업", "기타"],
    "GB": [420.0, 1180.0, 95.0, 260.0, 640.0, 45.0],
}

예시

기본 — labels= 를 주지 않으면 타일 번호가 이름이 된다

sp.treemap(STORAGE, values="GB")

labels= 로 타일에 이름을 붙인다

sp.treemap(STORAGE, values="GB", labels="종류")

타일이 작으면 라벨을 넣지 않는다 — 값이 고르지 않을수록 자주 일어난다

LOPSIDED = {
    "종류": ["동영상", "이미지", "문서", "캐시", "임시", "기타"],
    "GB": [3200.0, 180.0, 40.0, 22.0, 11.0, 6.0],
}
sp.treemap(LOPSIDED, values="GB", labels="종류")

tooltip=True — 라벨이 안 들어간 타일도 자기 이름을 말한다

LOPSIDED = {
    "종류": ["동영상", "이미지", "문서", "캐시", "임시", "기타"],
    "GB": [3200.0, 180.0, 40.0, 22.0, 11.0, 6.0],
}
sp.treemap(LOPSIDED, values="GB", labels="종류", tooltip=True)

메모

  • 네 번째 그림에는 체크박스가 없다. 타일 하나가 행 하나라서 토글을 달면 "3행을 끄시오" 가 되는데, 그건 범례가 아니라 데이터 편집이다.
  • tooltip=True 가 타일마다 <title> 에 이름·값·비율을 담는다. 라벨이 안 들어간 타일이 이름을 말하는 유일한 길이다 — 40x16px 보다 작으면 라벨을 안 그리는데, 그런 타일이야말로 독자가 찾아봐야 하는 타일이다. 범례가 이름을 갖고 있지만 squarified 배치에서 범례 줄과 타일을 맞추려면 색으로 뒤져야 한다.
  • 비율은 그림에 없는 사실을 더하는 게 아니라 그림을 읽어주는 것이다. 트리맵은 값을 면적으로 인코딩하므로 "40.0%" 는 그 타일의 크기가 뜻하는 바 그대로다. 소수점 한 자리로 적는다 — 비율은 독자가 눈으로도 보는 총합의 몫이지 측정값이 아니고, 열일곱 자리짜리 비율은 툴팁에서 가장 긴 것이 된다.
  • tooltip=True 일 때만 타일 안 라벨이 pointer-events: none 을 받는다. 라벨은 타일 *안*에 있어서 독자가 보는 바로 그 자리에서 포인터를 가져가고, 그러면 타일의 <title> 대신 라벨의 잘림 <title> 이 뜬다. tooltip=False 에서 조건을 거는 이유는 그 라벨 <title> 이 전문을 읽는 유일한 길이어서가 아니다 — 범례가 언제나 갖고 있고 범례 줄은 포인터를 잃지 않는다. 툴팁이 꺼져 있으면 타일에 <title> 이 아예 없어서, 라벨을 치우는 것이 아무것도 아닌 것과 맞바꾸는 일이 되기 때문이다.
  • 그 조건부가 막지 못하는 구멍 하나는 이름을 대 둔다. 120자를 넘는 이름은 타일 툴팁에서 빠지는데 그 이름을 든 라벨도 포인터에서 빠지므로, 독자가 올려놓는 바로 그 자리에 이름이 없다. 정보가 사라지는 건 아니다 — 범례 줄이 그대로 갖고 있다.
  • 단일 레벨이다. 계층형 트리맵은 범위 밖이고, 그것을 받으려면 데이터 입력이 트리가 되어야 한다.
  • 음수·비유한 값을 라벨명을 대고 거부하고, 합이 0 이면 거부한다.
  • 40x16 px 보다 작은 타일에는 라벨을 넣지 않는다. 반쯤 잘린 글자는 이름 노릇을 못 한다.
  • 타일 폭에 들어가지 않는 긴 라벨은 줄임표로 줄이고 전문을 <title> 에 남긴다. 보조기술과 브라우저 툴팁이 그것을 읽는다.
  • 항상 범례를 그린다. 작은 타일의 이름은 범례에서만 읽힌다.
